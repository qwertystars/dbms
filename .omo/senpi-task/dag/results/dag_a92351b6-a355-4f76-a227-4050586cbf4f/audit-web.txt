I read only the three scoped files (`web/app.js`, `web/index.html`, `web/style.css`) and wrote only the report. Highlights:

**Critical (1)**
- `app.js:125-126` — tab-switch handlers reference undeclared `fLogin`/`fSignup` identifiers, so clicking "Sign up" throws a ReferenceError and the signup form is unreachable (verified by grep: only the DOM ids `f-login`/`f-signup` exist).

**Medium (7)**
- `api()` content-type check misses `+json` types (RFC 7807 `application/problem+json`), hiding real error messages.
- `api()` returns `null` on 2xx non-JSON bodies, so `.user`/`.tree_id` reads throw opaque TypeErrors.
- `/api/me` failures are swallowed, silently bouncing logged-in users to login on transient 500s.
- `openBigModal` awaits without a catch, leaving the overlay stuck on "Loading person…" on any failure.
- Stored XSS via unescaped `b.gen` and `c.child_count` interpolations (the escaped fields `t.name`, `c.other_info`, `couple_id` are fine).
- `splitPartners` duplicates the first female partner into both father and mother slots for all-female couples.
- Signup re-sends signup FormData to `/api/login` and assumes `.user`, misreporting successful signups as failures.

**Low (4)**
- `#/tree/undefined` route renders a broken page if tree creation response lacks `tree_id`.
- Leaked `resize` listener throws after leaving the tree view (`#board` removed).
- Router catch only handles 401, leaving stale DOM under the current hash for other errors.
- Small-box positioning mixes document/viewport coordinates when scrolled.

Two earlier candidate findings were dropped during verification: the `esc()` attribute-interpolation concern is actually neutralized by escaping, and the empty-hash double-render claim was wrong (empty hash matches `#/login` directly).
